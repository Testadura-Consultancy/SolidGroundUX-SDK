SolidGroundUX Documentation
Deployment
sux-deployment_preface.sh:::Deployment:

SolidGroundUX deployment is built around three complementary tools:

prepare-release.sh
Builds complete, versioned release artifacts from a workspace.
deploy-workspace.sh
Streams selected development files directly to a target machine.
release-manager.sh
Standalone release acquisition, installation, update, rollback,
reinstallation, and removal.

Together they cover the two main deployment scenarios:

Development deployment
Fast transfer of selected workspace files without creating a formal release.
Release deployment
Creation, validation, installation, update, rollback, and removal of
complete SolidGroundUX releases.

The release manager is deliberately self-sufficient. It always carries a small standalone UI and default-theme fallback so it can bootstrap a clean machine or recover a damaged installation. When a healthy SolidGroundUX framework is available at the selected target root, the manager may reuse the normal framework UI primitives and active theme without making the release engine dependent on them.
