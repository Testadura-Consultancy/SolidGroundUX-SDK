Documentation Conventions
sdk-documentation_preface.sh::Documentation Generator:Documentation Conventions:

Documentation comments should be written as part of normal development, not as an afterthought at release time.

Module headers should be kept complete and current.

Public functions should include enough information for another developer to understand their purpose, expected inputs, output, return behavior, and typical usage.

Internal helpers may use shorter documentation, but should still explain intent when the behavior is not obvious.

Empty documentation separator lines should use a plain comment line rather than a quoted documentation line, to avoid stray quote markers in rendered output.
